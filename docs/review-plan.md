# План Code Review: Модуль скидок и корзины (src/discount.py)

## 1. Цели ревью
* **Точность расчетов:** Исключение ошибок округления чисел с плавающей точкой в финансовых операциях.
* **Защита от фрода (Anti-fraud):** Контроль за тем, чтобы суммарные скидки не превышали установленные бизнес-лимиты.
* **Безопасность:** Проверка валидности входных данных (отрицательные суммы, некорректные типы).

## 2. Измеримые критерии приемки (Quality Gates)
* **Отсутствие Magic Numbers:** Все коэффициенты скидок, лимиты (15000, 0.70, 0.85) вынесены в конфигурацию или константы.
* **Валидация данных:** Наличие валидатора входных параметров (например, через Pydantic).
* **Покрытие тестами:** Покрытие кода юнит-тестами должно составлять не менее **85%**.

## 3. Участники и роли
* **Автор кода:** Разработчик микросервиса.
* **Ревьюер:** Tech Lead (Никнейм на GitHub).
* **Бизнес-определитель (опционально):** Product Owner (для сверки логики акций).

## 4. Порядок разрешения споров (Эскалация)
В случае возникновения архитектурных разногласий или споров по реализации:
1. Фиксация аргументов сторон в комментариях к Pull Request.
2. Проведение короткого 15-минутного созвона (Sync Call) для выработки компромисса.
3. Если компромисс не найден, финальное решение принимает **Tech Lead** проекта.
